# Local server implementation contract

The Node server uses `.mjs` modules, Fastify, plain PostgreSQL, and Web Request/Response handlers. Production has no Supabase SDK or hosted calls.

`server/database.mjs` exports `pool`, a `pg.Pool`. Timestamp/date parsers return ISO strings. The application tables keep their original columns. Foreign keys formerly pointing at `auth.users` point at local `users`.

`server/auth.mjs` exports `getUser(request)`, returning the authenticated user or null, and `requireUser(request)`, throwing on missing auth. Users have `id`, `email`, `role`, `created_at`, `last_sign_in_at`, `user_metadata`, and `app_metadata`. Passwords are bcrypt, imported verbatim. Browser cookies and native opaque bearer credentials resolve to the same local users.

`server/repository.mjs` exports `repositoryFor(request)` and `adminRepository`. These are private server adapters for mechanically porting proven provider algorithms. They are not exposed as query APIs to clients. They support the existing internal query methods `.from(table)`, `.select(columns, options)`, `.eq(column,value)`, `.gte(column,value)`, `.order(column,options)`, `.limit(n)`, `.maybeSingle()`, `.single()`, `.insert(rows)`, `.upsert(rows,{onConflict})`, `.update(values)`, `.delete()`, and `.rpc(name,args)`. Awaited values return `{data,error,count}`. Identifier allowlists and parameterized SQL are mandatory. The user repository enforces ownership; the admin repository is importable only on the server. `repository.auth.getUser()` returns `{data:{user},error}`, and admin `.auth.admin.listUsers({page,perPage})` and `.deleteUser(id)` support the owner dashboard/account cleanup.

The private adapter has `.storage.from(bucket)` supporting `.download(path)` as a Blob, `.upload(path,bytes,{contentType,upsert})`, `.remove(paths)`, `.list(folder,{limit,offset,sortBy})`, `.createSignedUrls(paths,seconds)`, and `.getPublicUrl(path)`. Paths are restricted to local bucket storage; private downloads use signed grants. No remote storage API remains.

Backend action handlers live at `server/handlers/<name>.mjs` and export `handler(request): Promise<Response>`. Replace `Deno.serve` with that export, environment reads with `process.env`, and edge background tasks with the durable local queue. Root mounts actions at `/api/actions/<name>` and handles methods/authentication in a route ledger. Existing JSON/SSE payloads stay compatible. Social functions must replace remote Auth/REST fetches with local auth and repository calls. Keep legacy Stripe metadata readers for existing customers.

The browser client lives at `src/api.ts` and exposes `api.auth`, `api.library`, `api.account`, `api.invoke(name,{body})`, `api.assets`, and `actionUrl(name)`. Use same-origin requests with cookies. Auth methods preserve the existing `{data,error}` UI result shape where useful, but no table/query builder is public. `Session` and `User` come from the local client, not Supabase types. Native API calls use the same product operations with bearer credentials.

Canonical library routes are `GET/POST /api/library`, `PATCH/DELETE /api/library/:id`, `GET /api/library/:id/file`, and `GET /api/library/:id/pages`. Upload uses multipart `metadata` JSON plus `file` bytes, authorizes the caller, and commits storage and book metadata as one recoverable operation. `/api/account/summary` returns billing profile, image usage, and saved image counts. `/api/auth/session`, `/api/auth/sign-in`, `/api/auth/sign-up`, `/api/auth/sign-out`, `/api/auth/refresh`, and `/api/auth/oauth/:provider` own authentication. Google sign-in starts at `POST /api/auth/oauth/google` and returns to `GET|POST /api/auth/oauth/google/callback`; with `GOOGLE_CLIENT_SECRET` set it uses the authorisation-code flow, and without it Google posts a signed `id_token` back instead, so the secret is optional. A failed sign-in redirects to the return path with `?auth_error=<message>` rather than rendering a JSON error. Raw storage paths never authorize a request.
